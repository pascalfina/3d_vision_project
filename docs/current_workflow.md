# Current Scene Workflow

This is the short map of the current profile-based Object-X workflow. The goal
is to make clear where the important files come from and which later step uses
them.

## Mental Model

The current pipeline uses three dataset roots:

```text
baseline root       original prepared Object-X / Scan3R data
reconstruction root SAM2 + pose/depth + voxelised object geometry
pred-ready root     final staged root consumed by SLAT / U3DGS
```

In each profile these are configured under:

```json
"roots": {
  "baseline": "...",
  "reconstruction": "...",
  "pred_ready": "..."
}
```

The most important thing to understand early:

```text
baseline/files/objects.json
```

is the original object metadata from the prepared dataset.

```text
reconstruction/files/objects_sam2.json
```

is only a SAM2 track registry / debug file.

```text
pred_ready/files/objects.json
```

is the final object list used by SLAT and U3DGS. It is generated by
`build-pred-ready` from the reconstructed objects that survived voxelisation.

So when debugging downstream inference, always check the pred-ready
`files/objects.json`, not only the SAM2 registry.

## Main Entrypoint

Run one stage through:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> <action>
```

Profiles live in:

```text
configs/workflows/scene_profiles/
```

Useful command:

```bash
bash scripts/workflows/run_scene_profile.sh --list-profiles
```

Before expensive runs:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> <action> --dry-run
```

The dispatcher is:

```text
scripts/workflows/run_scene_profile.py
```

It reads the profile and calls the correct wrapper/script for the requested
action.

## Important Configs

```text
configs/workflows/scene_profiles/*.json
```

Main configs. They define scene id, roots, mask source, scene source directory,
stage logs, and stage-specific environment variables.

```text
configs/workflows/input_variants.json
```

Defines defaults for variants such as `legacy`, `legacy+sam`, and
`legacy+sam+must3r`.

```text
preprocessing/segmentation/pipeline.yaml
```

Low-level defaults for SAM2, MUSt3R, MASt3R-SfM, keyframe selection, and output
folder names. Profiles usually override the important values via environment
variables.

```text
preprocessing/voxel_anno/voxel_anno.yaml
```

Voxelisation / DINO feature extraction config.

```text
configs/config.yaml
```

SLAT / U3DGS inference config.

## End-To-End Stages

### 1. Baseline Dataset

This already exists before our current workflow starts.

Important files:

```text
<baseline>/files/3RScan.json
<baseline>/files/objects.json
<baseline>/files/orig/data/<scene_id>.pkl.gz
<baseline>/files/Features3D/
<baseline>/files/gt_projection/obj_id_pkl/<scene_id>.pkl
<baseline>/scenes/<scene_id>/sequence.zip or sequence/
```

The current profile workflow does not create the full baseline dataset. It
builds new roots on top of it.

### 2. `segment-inputs`

Command:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> segment-inputs
```

Main code:

```text
preprocessing/segmentation/run_pipeline.py
preprocessing/segmentation/segment_sam2.py
utils/object_registry.py
```

Creates SAM2 masks:

```text
<reconstruction>/files/sam2_projection/obj_id_pkl/<scene_id>.pkl
<reconstruction>/files/sam2_projection/obj_id/<scene_id>/frame-*.jpg
<reconstruction>/files/objects_sam2.json
```

`obj_id_pkl/<scene_id>.pkl` is the important machine-readable mask file.
`objects_sam2.json` is not the final Object-X object registry.

### 3. `must3r`, `mast3r-sfm`, and `fuse`

These steps create pose/depth scene variants.

Typical commands:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> must3r
bash scripts/workflows/run_scene_profile.sh <profile> mast3r-sfm
bash scripts/workflows/run_scene_profile.sh <profile> fuse
```

Main code:

```text
preprocessing/segmentation/depth_pose_must3r.py
preprocessing/segmentation/depth_pose_mast3r_sfm.py
preprocessing/segmentation/fuse_must3r_pose_mast3r_sfm_depth.py
```

Typical output:

```text
<reconstruction>/scenes_sam2_must3r/<scene_id>/sequence/frame-*.pose.txt
<reconstruction>/scenes_sam2_must3r/<scene_id>/sequence/frame-*.depth.pgm
<reconstruction>/scenes_sam2_must3r/<scene_id>/sequence/frame-*.depth_raw.npy
<reconstruction>/scenes_sam2_must3r/<scene_id>/sequence/frame-*.conf.npy
<reconstruction>/scenes_sam2_must3r/<scene_id>/sequence/frame-*.xyz.npy
```

The exact scene folder depends on the profile, for example:

```text
scenes_sam2
scenes_sam2_must3r
scenes_sam2_mast3r_sfm
scenes_sam2_mast3r_sfm_must3r
```

The voxelise stage chooses which one to read with:

```json
"voxelise": {
  "scene_source_dirname": "scenes_sam2_must3r"
}
```

### 4. `voxelise`

Command:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> voxelise
```

Main code:

```text
scripts/voxel_annotations/pipeline/run_scanwise_voxelise_tmp.py
preprocessing/voxel_anno/voxelise_features.py
```

Reads:

```text
<reconstruction>/files/<mask_source>/obj_id_pkl/<scene_id>.pkl
<reconstruction>/<scene_source_dirname>/<scene_id>/sequence/
<baseline>/files/objects.json
```

Important: mask source and object registry are separate. A SAM2 run can use:

```text
masks:   reconstruction/files/sam2_projection/obj_id_pkl/<scene_id>.pkl
objects: baseline/files/objects.json
```

This only makes sense if the mask object ids match the object ids expected by
`objects.json`.

Creates one folder per reconstructed object:

```text
<reconstruction>/files/gs_annotations/<scene_id>/<obj_id>/voxel_output_dense.npz
<reconstruction>/files/gs_annotations/<scene_id>/<obj_id>/mean_scale_dense.npz
```

Meaning:

- `voxel_output_dense.npz` contains object voxels plus DINO features.
- `mean_scale_dense.npz` stores the object normalization.

Objects can disappear here if masks/depth/poses are bad or not enough geometry
is produced.

### 5. `build-pred-ready`

Command:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> build-pred-ready
```

Main code:

```text
scripts/segmentation/pipeline/build_pred_ready_scene_root.py
```

Reads:

```text
<baseline>/files/objects.json
<baseline>/files/orig/data/<scene_id>.pkl.gz
<reconstruction>/files/gs_annotations/<scene_id>/<obj_id>/
```

Keeps only objects with:

```text
voxel_output_dense.npz
mean_scale_dense.npz
voxel_count >= min_voxels
```

Creates the final dataset root:

```text
<pred_ready>/files/objects.json
<pred_ready>/files/orig/data/<scene_id>.pkl.gz
<pred_ready>/files/gs_annotations/<scene_id>/<obj_id>/  -> symlink to reconstruction
<pred_ready>/files/pred_ready_scene_manifest.json
<pred_ready>/scenes/<scene_id>/sequence/
```

This is the step that generates the final `objects.json` used by downstream
inference.

### 6. `validate-pred-ready` and `compare-arrangement`

Commands:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> validate-pred-ready
bash scripts/workflows/run_scene_profile.sh <profile> compare-arrangement
```

Main code:

```text
scripts/segmentation/validation/validate_pred_ready_scene_root.py
scripts/segmentation/validation/compare_scene_arrangement.py
```

These are checks. They do not create the core inference inputs.

### 7. `slat`

Command:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> slat
```

Main code:

```text
scripts/inference/pipeline/run_pipeline_slat_tmp.sh
scripts/inference/pipeline/run_pipeline_tmp.py
src/inference/structured_latent_inference.py
```

Reads the pred-ready root:

```text
<pred_ready>/files/objects.json
<pred_ready>/files/orig/data/<scene_id>.pkl.gz
<pred_ready>/files/gs_annotations/<scene_id>/
<pred_ready>/files/Features3D/
<pred_ready>/scenes/<scene_id>/sequence/
```

Writes:

```text
<pred_ready>/files/gs_embeddings/<scene_id>_slat.npz
```

### 8. `u3dgs`

Command:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> u3dgs
```

Main code:

```text
scripts/inference/pipeline/run_pipeline_u3dgs_tmp.sh
scripts/inference/pipeline/run_pipeline_tmp.py
src/inference/unstructured_latent_inference.py
```

Reads:

```text
<pred_ready>/files/gs_embeddings/<scene_id>_slat.npz
<pred_ready>/files/objects.json
<pred_ready>/files/orig/data/<scene_id>.pkl.gz
<pred_ready>/files/gs_annotations/<scene_id>/
```

Writes embeddings and visualization outputs such as:

```text
<pred_ready>/files/gs_embeddings/<scene_id>_ulat.npz
<pred_ready>/vis/<scene_id>_joint.ply
```

### 9. `render`

Command:

```bash
bash scripts/workflows/run_scene_profile.sh <profile> render
```

Main code:

```text
scripts/segmentation/visualization/render_joint_depth_background_bundle.sh
scripts/segmentation/visualization/render_joint_depth_background.py
```

Creates the final inspection bundle, usually HTML plus MP4, under:

```text
vis/rendered_joint_depth_bg/
```

This is for visual debugging, not for model input.

## Debugging Order

When a run looks wrong, inspect in this order:

1. Profile: `configs/workflows/scene_profiles/<profile>.json`
2. Roots: `baseline`, `reconstruction`, `pred_ready`
3. Mask source: `OBJECTX_MASK_SOURCE` / `mask_source`
4. Pose-depth source: `voxelise.scene_source_dirname`
5. SAM2 masks: `<reconstruction>/files/sam2_projection/obj_id_pkl/<scene_id>.pkl`
6. Voxelised objects: `<reconstruction>/files/gs_annotations/<scene_id>/<obj_id>/`
7. Pred-ready object list: `<pred_ready>/files/objects.json`
8. Pred-ready scene graph: `<pred_ready>/files/orig/data/<scene_id>.pkl.gz`
9. SLAT output: `<pred_ready>/files/gs_embeddings/<scene_id>_slat.npz`
10. U3DGS / render outputs
